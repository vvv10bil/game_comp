# Звіт по проєкту: CS2 Companion

> Курсова робота з JavaScript. Веб-додаток-компаньон для гри
> **Counter-Strike 2** з персональним кабінетом, журналом матчів,
> менеджером лоудаутів і каталогом зброї.

---

## 1. Що реалізовано

Додаток складається з двох частин — **REST API на Node.js** та
**SPA на React**, об'єднаних у monorepo з npm-workspaces.

### 1.1 Автентифікація
- Реєстрація: email + нікнейм + пароль (мінімум 8 символів).
- Логін з перевіркою хешу пароля.
- Паролі зберігаються як **bcrypt-хеш** (10 раундів) — у відкритому
  вигляді не зберігаються ніколи.
- Сесія підтримується через **JWT-токен у `httpOnly` cookie** (захист
  від XSS-крадіжки токена).
- Захищені маршрути: middleware `requireAuth` перевіряє JWT перед
  кожним зверненням до приватних ресурсів.
- Endpoint `/api/auth/me` — отримання профілю поточного користувача.
- Logout очищає cookie на стороні сервера.

### 1.2 Менеджер лоудаутів (CRUD)
Користувач може створювати, переглядати та видаляти власні лоудаути:
назва, сторона (T/CT), primary, secondary, ніж, нотатки. Кожен
лоудаут належить лише власнику — на рівні бекенда фільтрація йде по
`userId` з токена.

### 1.3 Журнал матчів
Логування зіграних матчів: мапа, результат (win/loss/draw), рахунок,
K/D/A. Окремий endpoint `/api/matches/stats` рахує агрегати:
кількість матчів, win rate, K/D-співвідношення.

### 1.4 Каталог зброї
Сторінка з фільтрами по стороні (T/CT) та категорії (rifle, sniper,
SMG, pistol). Дані зброї віддає бекенд із статичного словника
(спеціально не з БД, щоб показати різницю між публічним та
приватним ресурсом).

### 1.5 UI / UX
- Темна тема з акцентами в кольорах CS2 (помаранчевий/синій для T/CT).
- Адаптивна сітка: працює на мобільних і десктопі.
- Sticky-навбар, активний стан посилань, hover-стани.
- Картки статистики, таблиця матчів, форми з валідацією HTML5.

## 2. Архітектура

### 2.1 Загальна схема

```
┌─────────────────────────┐         ┌─────────────────────────┐
│      React (Vite)       │  HTTP   │   Express (Node.js)     │
│   localhost:5173        │ ──────► │   localhost:3000        │
│                         │ /api/*  │                         │
│  - React Router         │         │  - Routers              │
│  - AuthContext          │ ◄────── │  - Zod validation       │
│  - axios + cookies      │  JSON   │  - JWT middleware       │
└─────────────────────────┘         └────────────┬────────────┘
                                                 │ Prisma Client
                                                 ▼
                                       ┌──────────────────┐
                                       │   SQLite (file)  │
                                       │   prisma/dev.db  │
                                       └──────────────────┘
```

Vite-dev-сервер проксіює `/api/*` на Express — у браузері все на одному
origin, тому cookie з токеном доступне без CORS-проблем.

### 2.2 Шаруватість бекенду

Класичний поділ за відповідальностями:

| Шар           | Відповідальність                                    | Папка             |
| ------------- | ---------------------------------------------------- | ----------------- |
| Routes        | HTTP-маршрутизація, валідація вхідних даних (Zod)   | `server/src/routes` |
| Middleware    | Аутентифікація, обробка помилок                     | `server/src/middleware` |
| Data access   | Запити до БД через Prisma Client                     | `server/src/db.js` + Prisma |
| Schema (БД)   | Декларативна модель даних                            | `server/prisma/schema.prisma` |

Контролери винесені прямо в роутерах, оскільки логіка проста (CRUD).
Якщо ускладнюватиметься — легко витягнути в окремий `controllers/`.

### 2.3 Архітектура фронтенду

| Шар           | Відповідальність                                    | Папка             |
| ------------- | ---------------------------------------------------- | ----------------- |
| `api/`        | Тонкий axios-клієнт з `withCredentials: true`       | `client/src/api`  |
| `context/`    | Глобальний стан користувача (Context API)           | `client/src/context` |
| `pages/`      | Маршрутні сторінки (Login, Register, Dashboard, …)   | `client/src/pages` |
| `components/` | Перевикористовувані UI-блоки (Navbar)                | `client/src/components` |
| `styles/`     | Глобальні CSS-змінні та класи                        | `client/src/styles` |

Маршрутизація через React Router v6, захист через HOC-обгортку
`<Protected>` у `App.jsx`, що перенаправляє неавторизованих на `/login`.
Стан авторизації зберігається в `AuthContext` — будь-який компонент
викликає `useAuth()` для доступу до `user`, `login`, `register`, `logout`.

### 2.4 Модель даних

```
User ──┬─< Loadout
       └─< Match
```

- **User**: email (unique), username (unique), passwordHash, steamId.
- **Loadout**: name, side (T/CT), primary, secondary, knife, notes.
- **Match**: map, result, score, kills, deaths, assists, playedAt.

Каскадне видалення: при видаленні користувача всі його лоудаути та
матчі видаляються автоматично (`onDelete: Cascade`).

### 2.5 Безпека

- Паролі — лише як bcrypt-хеш, ніколи не повертаються з API.
- JWT у `httpOnly` cookie — JavaScript не може його прочитати.
- `sameSite: lax` — захист від CSRF на критичних запитах.
- Zod-валідація на бекенді — навіть якщо клієнт обійшов валідацію форми,
  невалідні дані не потраплять у БД.
- Авторизація на рівні рядків: `where: { userId: req.userId }` у всіх
  запитах до приватних ресурсів — користувач A не може видалити
  лоудаут користувача B.
- CORS налаштований лише на origin фронтенда, з `credentials: true`.

## 5. Як запустити

### У GitHub Codespaces
1. Створити codespace з гілки `main`.
2. Після `postCreateCommand` (auto): `npm install` + `prisma migrate dev`.
3. `npm run dev` — Codespaces зробить порт 5173 публічним і відкриє у браузері.

### Локально
```bash
npm install
cp server/.env.example server/.env
npm run db:init
npm run dev
```

Відкрити http://localhost:5173.

## 7. Підсумок

Проєкт демонструє повний цикл розробки сучасного веб-додатку на
JavaScript-стеку: декларативний фронтенд на React з SPA-маршрутизацією,
REST-бекенд з типобезпечним ORM, безпечну автентифікацію, чисту
шарувату архітектуру та готовність до запуску в хмарному dev-середовищі
(GitHub Codespaces).
